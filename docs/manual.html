1. Introducción

qbank es una librería Python para generar bancos de preguntas de opción múltiple cuyas respuestas correctas se determinan automáticamente mediante cálculo proposicional. A partir de una lista de supuestos y cuestiones, genera todas las variantes posibles de una pregunta combinando los elementos alternativos; para cada variante calcula qué respuestas son correctas y cuáles no, y exporta el resultado a LaTeX/AMC (exámenes en papel) o a Moodle. Se apoya en calcprop, el motor de cálculo proposicional.

Este documento es la referencia: la API, el formato JSON, los exportadores y el comprobador lint, con sus firmas exactas. No es el sitio por donde empezar:

  • README.org explica cómo instalar y cómo crear un banco con qbank-init.
  • Tutorial.ipynb recorre cinco ejemplos progresivos ejecutables.
  • La Guía de diseño (GuiaDiseno.org, impresa en GuiaDiseno.pdf) explica cómo diseñar buenas preguntas: la mecánica de listas y mundos, el patrón recomendado, la redacción y las trampas de LaTeX y Moodle.

Los ejemplos ejecutables de este manual cargan los JSON de la carpeta ejemplosManual/, que está en el repositorio pero no viene con pip install. Para ejecutarlos, clona el repositorio (git clone https://github.com/mbujosab/calcprop-qbank) y lánzalos desde su carpeta raíz. Para crear tu banco no hace falta: qbank-init trae sus propias preguntas de ejemplo.

El vocabulario que usa este manual es el de la Guía: variante (cada versión concreta de la pregunta), mundo (las hipótesis activas en una variante), hueco (cada posición que se convierte en una opción: una Cuestion suelta o una lista de la que se sortea una), parte (cada bloque de opciones de una pregunta con varios), opción por defecto («Ninguna de las anteriores», que añade export.last_choice) y vista profe (todas las cuestiones de cada hueco con sus marcas).

1.1. Instalación rápida (para quien ya conoce Python)

pip install calcprop-qbank

qbank-init y lint llegan con la 0.6.0; si tenías una versión anterior, actualiza con pip install -U calcprop-qbank. La versión en desarrollo se instala desde el repositorio (hace falta git): 

pip install "calcprop-qbank[jupyter] @ git+https://github.com/mbujosab/calcprop-qbank"

Si no estás familiarizado con Python o los entornos virtuales, lee la sección siguiente.

2. Instalación paso a paso

2.1. Requisitos previos

qbank requiere Python 3.9 o superior. Comprueba si ya lo tienes instalado:

Sistema Comando en terminal
Linux python3 --version
macOS python3 --version
Windows py --version

Si el comando devuelve algo como Python 3.11.2 estás listo. Si no, descarga Python desde python.org e instálalo (en Windows marca la opción Add Python to PATH).

2.2. Qué es un entorno virtual y por qué usarlo

Un entorno virtual es una carpeta que contiene una copia aislada de Python con sus propios paquetes instalados, independiente del resto del sistema. Esto evita conflictos entre proyectos que requieren versiones distintas de las mismas librerías.

Trabajar siempre dentro de un entorno virtual es una buena práctica, aunque no es estrictamente obligatorio para un uso sencillo de qbank.

2.3. Crear y activar un entorno virtual

Abre una terminal (en Windows: Símbolo del sistema o PowerShell) y sitúate en el directorio donde quieres trabajar, por ejemplo: 

mkdir mis_cuestionarios
cd mis_cuestionarios

Crea el entorno virtual (llámalo como quieras; aquí usamos .venv):

Sistema Comando
Linux / macOS python3 -m venv .venv
Windows (cmd) py -m venv .venv
Windows (PS) py -m venv .venv

Actívalo:

Sistema Comando
Linux / macOS source .venv/bin/activate
Windows (cmd) .venv\Scripts\activate.bat
Windows (PowerShell) .venv\Scripts\Activate.ps1

Cuando el entorno está activo, verás su nombre entre paréntesis al comienzo del prompt, por ejemplo (.venv). A partir de ese momento, pip y python apuntan al entorno virtual y no al sistema.

2.4. Instalar calcprop-qbank

Con el entorno activo: 

pip install calcprop-qbank

o, para la versión en desarrollo (hace falta tener git): 

pip install "calcprop-qbank[jupyter] @ git+https://github.com/mbujosab/calcprop-qbank"

Verifica la instalación: 

python -c "import qbank; print('qbank', qbank.__version__)"
qbank-init --help

Si ves qbank 0.6.0 (o posterior) y la ayuda de qbank-init, todo está en orden. Si en cambio sale AttributeError: … no attribute '__version__' o qbank-init no existe, tienes una versión anterior a la 0.6: actualiza con pip install -U calcprop-qbank. Para los PDF y el XML de Moodle hace falta además pdflatex con los paquetes automultiplechoice (lo instala el programa Auto Multiple Choice) y moodle (tlmgr install moodle en TeX Live).

2.5. Nota para usuarios de Windows

En Windows, dentro del entorno virtual, usa python (no python3). Si al activarlo en PowerShell (.venv\Scripts\Activate.ps1) sale un error de permisos, ejecuta antes: 

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

2.6. Crear un banco de preguntas

La forma recomendada de trabajar es un proyecto creado con qbank-init: 

qbank-init mi-banco
cd mi-banco
make lint          # comprueba las preguntas de ejemplo (sin LaTeX)
make amc           # PDF de revisión (vista profe) en build/amc/

El proyecto contiene cinco preguntas de ejemplo, los scripts que las exportan, un Makefile y nueva_pregunta.py, un guion para escribir una pregunta en Python y guardarla como JSON. Su README.org explica el flujo completo. El resto de este manual describe las piezas que esos scripts usan.

3. Conceptos fundamentales

3.1. Fórmulas con calcprop

qbank importa calcprop, así que al escribir from qbank import * tienes acceso al motor lógico. Las variables proposicionales (en la Guía, etiquetas) se crean con v() y los nombres los eliges tú; solo tienen que ser consistentes dentro de la misma pregunta: 

from qbank import *

A = v('A')    # variable proposicional A

Las fórmulas se construyen combinando variables con los operadores de Python:

Operador Python Conectiva lógica Ejemplo
-v('A') Negación (¬A) -v('A')
v('A') & v('B') Conjunción (A \(\land\) B) v('A') & v('B')
v('A') | v('B') Disyunción (A \(\lor\) B) v('A') | v('B')
v('A') >> v('B') Implicación (A \(\implies\) B) v('A') >> v('B')
v('A') ** v('B') Bicondicional (A \(\iff\) B) v('A') ** v('B')
alguno(v('A'), v('B'), v('C')) Alguna verdadera alguno(v('A'), v('B'), v('C'))
unoDe(v('A'), v('B'), v('C')) Exactamente una verdadera unoDe(v('A'), v('B'), v('C'))

La semántica también acepta True (siempre verdadero) o False (siempre falso). alguno y unoDe aceptan cualquier número de proposiciones.

Atención — precedencia de operadores: la precedencia de Python difiere de la lógica matemática. En lógica, → tiene menor precedencia que ∧ y ∨, por lo que A ∧ B → C se lee como (A ∧ B) → C. En Python, >> tiene mayor precedencia que & y |, así que v('A') & v('B') >> v('C') se evalúa como v('A') & (v('B') >> v('C')), que no es lo que se espera. Usa siempre paréntesis explícitos en implicaciones compuestas: 

(v('A') & v('B')) >> v('C')   # correcto: (A ∧ B) → C
v('A') & v('B') >> v('C')     # incorrecto: A ∧ (B → C)

La función test(formula, hipotesis) comprueba si una fórmula es consecuencia lógica de una lista de fórmulas hipótesis: 

test(v('C'), [v('A'), v('A') >> v('C')])    # True  (modus ponens)
test(v('C'), [v('B')])                      # False (B no implica C)
test(True,   [])                            # True
test(False,  [])                            # False

No necesitas llamar a test directamente: qbank lo invoca al generar las variantes. Conviene tener presente lo que responde: «¿se deduce esto de las hipótesis?», no «¿es verdad?». De la hipótesis v('crec') no se sigue -v('decr'), salvo que un axioma declare que ambas son excluyentes (unoDe(v('crec'), v('decr'))).

3.2. Supuesto — una hipótesis del enunciado

Un Supuesto es una afirmación que se añade al enunciado del problema y cuya semántica se incorpora como hipótesis para evaluar las cuestiones que le siguen. 

Supuesto(enunciado, semantica, precond=True)
Parámetro Tipo Descripción
enunciado cadena Texto LaTeX del supuesto, tal como aparecerá impreso. Admite @{variable} (ver setup).
semantica fórmula Fórmula proposicional que el supuesto afirma verdadera.
precond fórmula/bool El supuesto solo se activa si esta precondición se cumple bajo las hipótesis ya acumuladas. Por defecto True (siempre activo).

Un Supuesto con enunciado vacío es un axioma: añade su fórmula sin texto. 

Supuesto('$\\mathcal{A}$ es verdadero. ', v('A'))
Supuesto('$\\mathcal{A} \\Rightarrow \\mathcal{C}$. ', v('A') >> v('C'))
Supuesto('', unoDe(v('inv'), v('sing')))          # axioma: los dos mundos son excluyentes

Si la precondición de un supuesto no se cumple en una variante concreta, esa variante se descarta.

3.3. Cuestion — un ítem de respuesta

Una Cuestion es una posible respuesta. qbank determina si es correcta o no según las hipótesis activas en cada variante. 

Cuestion(enunciado, semantica, precond=True, exp="")
Parámetro Tipo Descripción
enunciado cadena Texto LaTeX del ítem de respuesta. Admite @{variable}.
semantica fórmula/bool Fórmula cuya veracidad (como consecuencia de las hipótesis) determina si el ítem es correcto.
precond fórmula/bool La cuestión solo aparece si esta precondición se satisface; si no, la variante se descarta. Por defecto True.
exp cadena Explicación (retroalimentación) que Moodle muestra tras responder. Admite @{variable}. Opcional. 
Cuestion("Entonces $\\mathcal{C}$ es verdadero", v("C"))
Cuestion("Esta afirmación es siempre falsa", False)
Cuestion("$\\mathcal{B}$ es consecuencia de $\\mathcal{A}$", v("B"), precond=v("A"))
Cuestion("$f(@{a}) < f(@{b})$", v("crec"), exp="Porque $@{a} < @{b}$ y $f$ es creciente.")

Semánticas y precondiciones como cadenas. Tanto Supuesto como Cuestion aceptan semantica y precond escritas como la cadena que las representa ("v('A') >> v('B')", "True", "lambda ns: ns['x'] > 0"), que es exactamente lo que guarda el formato JSON. Es la forma de escribir una lambda en Python si la pregunta se va a guardar con save_problema: una función Python no se puede serializar; su cadena, sí.

3.4. ProblemaTipo — un generador de variantes

ProblemaTipo toma una lista plana de componentes y genera todas las combinaciones posibles, una variante por cada combinación. 

ProblemaTipo(componentes, setup=None, export=None, seed=None, nombre=None)
Parámetro Descripción
componentes Lista plana de cadenas (texto fijo), Supuesto y Cuestion, sueltos o en listas de alternativas (ver abajo).
setup Código Python como cadena (lo que guarda el JSON) o función sin argumentos que devuelve un dict. Se ejecuta antes de cada variante.
export Dict con las preferencias de exportación: last_choice, cols, instances. Lo leen los scripts de un banco, no las funciones.
seed Entero que siembra numpy.random y random antes de recorrer las variantes (solo tiene sentido con setup aleatorio).
nombre Identificador del problema (el campo nombre del JSON; debe coincidir con el nombre del fichero).

Las funciones de exportación no leen export: pasa tú last_choice=, instances= y cols= a AMCblock, QuizMoodle, QuizAMCProfe y las demás (los ejemplos de este manual lo hacen). Los scripts de un banco de qbank-init sí lo leen de cada JSON.

3.4.1. La mecánica: listas = sorteo, elementos consecutivos = opciones

Cada componente es, o bien un valor suelto (siempre se incluye), o bien una lista de dos o más valores del mismo tipo, de la que se sortea uno en cada variante. El número de variantes es el producto de las longitudes de las listas.

  • Una lista de Supuesto son mundos alternativos: se activa uno por variante.
  • Una lista de Cuestion no son «las opciones que se muestran juntas»: es un hueco del que se sortea una. El alumno ve tantas opciones como elementos-Cuestion consecutivos haya (sueltos o listas), más la opción por defecto si export.last_choice está activo.
  • Cuando tras un bloque de cuestiones vuelve a aparecer texto o un Supuesto, se abre una parte nueva (una pregunta con varios bloques de opciones). Las hipótesis se acumulan a lo largo de las partes.

El patrón recomendado es tres huecos + "export": {"last_choice": true}: cuatro opciones, con la garantía de que al menos una es correcta y al menos una incorrecta. La Guía desarrolla todo esto; aquí basta un ejemplo completo.

3.4.2. Ejemplo

from qbank import *

p = ProblemaTipo(
    [
        "Considere ",
        [   # dos mundos: se sortea uno
            Supuesto("$\\mathcal{A}$ ", v("A")),
            Supuesto("$\\mathcal{B}$ ", v("B")),
        ],
        [   # y otros dos, independientes de los anteriores
            Supuesto("y que $\\mathcal{A}\\Rightarrow\\mathcal{C}$. ", v("A") >> v("C")),
            Supuesto("y que $\\mathcal{B}\\Leftrightarrow\\mathcal{D}$. ", v("B") ** v("D")),
        ],
        "Entonces, con toda seguridad: ",
        [   # hueco 1
            Cuestion("se da $\\mathcal{C}$", v("C")),
            Cuestion("se da $\\mathcal{D}$", v("D")),
        ],
        [   # hueco 2
            Cuestion("se da $\\mathcal{A}$", v("A")),
            Cuestion("se da $\\mathcal{B}$", v("B")),
        ],
        [   # hueco 3
            Cuestion("se dan $\\mathcal{A}$ y $\\mathcal{C}$", v("A") & v("C")),
            Cuestion("se dan $\\mathcal{B}$ y $\\mathcal{D}$", v("B") & v("D")),
            Cuestion("se da $\\mathcal{E}$", False),
        ],
    ],
    export={"last_choice": True, "cols": 2},
    nombre="ejercicio",
)

for etiqueta, partes in p.por_partes():
    for enunciado, cuestiones in partes:
        print(f"Variante {etiqueta}: {enunciado}")
        for texto, correcto, activa, exp in cuestiones:
            print(f"  {'✓' if correcto else '✗'} {texto}")
    if int(etiqueta) == 3:
        break
print("…", len(list(p.por_partes())), "variantes en total")

Variante 1: Considere $\mathcal{A}$ y que $\mathcal{A}\Rightarrow\mathcal{C}$. Entonces, con toda seguridad:
  ✓ se da $\mathcal{C}$
  ✓ se da $\mathcal{A}$
  ✓ se dan $\mathcal{A}$ y $\mathcal{C}$
Variante 2: Considere $\mathcal{A}$ y que $\mathcal{A}\Rightarrow\mathcal{C}$. Entonces, con toda seguridad:
  ✓ se da $\mathcal{C}$
  ✓ se da $\mathcal{A}$
  ✗ se dan $\mathcal{B}$ y $\mathcal{D}$
Variante 3: Considere $\mathcal{A}$ y que $\mathcal{A}\Rightarrow\mathcal{C}$. Entonces, con toda seguridad:
  ✓ se da $\mathcal{C}$
  ✓ se da $\mathcal{A}$
  ✗ se da $\mathcal{E}$
… 48 variantes en total

\(2 \times 2 \times 2 \times 2 \times 3 = 48\) variantes, cada una con tres opciones más «Ninguna de las anteriores» (que el exportador añade y que en la variante 1 será incorrecta). ejemplosManual/ejercicio.json guarda este mismo problema en JSON, con una explicación (exp) en cada cuestión que aquí se omite por brevedad.

3.4.3. Iterar las variantes

por_partes(instances=1, base_seed=None, verbose=False)
la vía recomendada. Devuelve (etiqueta, [(enunciado, cuestiones), …]), un par por parte; cuestiones es una lista de tuplas (texto, correcto, activa, exp). Con setup aleatorio, instances=N recorre las variantes \(N\) veces con semillas distintas (base_seed + i * 997; si no se pasa base_seed se usa seed, y si tampoco hay seed, 42). Con instances=1 y sin ninguna de las dos no se siembra nada: el resultado depende del estado del generador. Con verbose=True imprime los supuestos y cuestiones rechazados por su precondición.
por_partes_profe(verbose=True)
la vista profe: el mismo formato, pero con todas las cuestiones de cada hueco (no una por variante) y las rechazadas por su precondición marcadas como 'rechazada por …' en vez de descartar la variante. Es lo que conviene revisar antes de dar una pregunta por buena.
for etiqueta, enunciado, cuestiones in p
el protocolo histórico, solo para ejercicios de una parte (con varias lanza ValueError).

3.5. Preguntas paramétricas con setup

El parámetro setup permite que los valores numéricos o simbólicos cambien en cada variante. En cada iteración:

  1. Se ejecuta el setup y sus variables forman el espacio de nombres ns de la variante.
  2. Los textos (enunciados, cuestiones y exp) que contengan marcadores @{variable} reciben la sustitución.
  3. Las semánticas y precondiciones que sean lambda ns: ... se evalúan con ese diccionario.

El delimitador @ se eligió para evitar conflictos con el modo matemático de \LaTeX{}. Para una arroba literal, escribe @@.

3.5.1. setup como cadena, np.random y seed

Escribe el setup como cadena de código (es lo que guarda el JSON, y la única forma que save_problema puede serializar) y usa np.random, no random: seed siembra numpy.random y random, pero los scripts de la vista profe de un banco solo siembran numpy. 

p = ProblemaTipo(
    [
        "Sean $a = @{a}$ y $b = @{b}$. Entonces:",
        [
            Cuestion("$a + b = @{suma}$", True),
            Cuestion("$a + b = @{suma_falsa}$", False, exp="$@{a} + @{b} = @{suma}$."),
        ],
        [
            Cuestion("$a + b > 10$", "lambda ns: ns['a'] + ns['b'] > 10"),
            Cuestion("$a + b < 10$", "lambda ns: ns['a'] + ns['b'] < 10"),
        ],
        Cuestion("$a \\cdot b = @{producto}$", True),
    ],
    setup="import numpy as np\n"
          "a, b = (int(x) for x in np.random.randint(1, 10, 2))\n"
          "suma, suma_falsa, producto = a + b, a + b + 1, a * b",
    seed=1,
    export={"last_choice": True, "instances": 15},
)
  • @{a}, @{b}, @{suma} se interpolan con los valores de cada variante.
  • Las lambdas, escritas como cadena, se evalúan con los valores de la variante.
  • seed=1 hace la pregunta reproducible; instances=15 recorre 15 veces (15 instancias) las 4 combinaciones (60 variantes, el mínimo que recomienda lint con setup).

El iterador es finito aunque el setup sea aleatorio: recorre una vez cada combinación de alternativas y llama al setup en cada una. Para obtener más instancias se usa instances, no un bucle a mano.

3.5.2. Precondiciones que dependen de los valores

El motor razona de forma proposicional y no conoce los valores numéricos: si ofreciéramos los supuestos «\(a > b\)» y «\(a < b\)» sin más, podría generar una variante con a = 3, b = 7 y el texto «Se sabe que \(a > b\)». La solución es una precondición lambda ns: ... que solo deja pasar la variante cuando la afirmación es cierta para los valores sorteados: 

ordenar = ProblemaTipo(
    [
        "Sean $a = @{a}$ y $b = @{b}$ dos números naturales. Se sabe que ",
        [
            Supuesto("$a > b$. ", True, precond="lambda ns: ns['a'] > ns['b']"),
            Supuesto("$a < b$. ", True, precond="lambda ns: ns['a'] < ns['b']"),
            Supuesto("$a = b$. ", True, precond="lambda ns: ns['a'] == ns['b']"),
        ],
        "Indique qué afirmación es correcta: ",
        [
            Cuestion("$a - b > 0$", "lambda ns: ns['a'] - ns['b'] > 0"),
            Cuestion("$b - a > 0$", "lambda ns: ns['b'] - ns['a'] > 0"),
        ],
        [
            Cuestion("$a^2 > b^2$", "lambda ns: ns['a'] ** 2 > ns['b'] ** 2"),
            Cuestion("$a^2 < b^2$", "lambda ns: ns['a'] ** 2 < ns['b'] ** 2"),
        ],
        Cuestion("$a \\cdot b > 0$", True),
    ],
    setup="import numpy as np\na, b = (int(x) for x in np.random.randint(2, 10, 2))",
    seed=7,
    export={"last_choice": True, "instances": 15},
)

Para cada combinación el setup genera una tirada nueva; si su precondición no se cumple, esa variante se descarta (con verbose=True verás, por ejemplo, el mensaje Supuesto: … rechazado por …). Por eso el número de variantes por instancia no es fijo: de las \(3 \times 2 \times 2 = 12\) combinaciones sobreviven unas cinco por instancia (las del supuesto que coincide con la tirada), y lint calcula que hacen falta 14 instancias para llegar a 60 (con las 15 de export salen 69). El problema ejemplosManual/numeros.json (el que carga el editor visual del cuaderno Demo.ipynb) es una versión ampliada de esta idea.

Con precondiciones numéricas, por_partes_profe() hace un solo sorteo por mundo, y un mundo cuya precondición no se cumple en ese sorteo no aparece: con seed=7, ordenar.por_partes_profe() muestra los tres mundos, pero con otra semilla podría mostrar menos (con seed=2, ninguno). La vista profe de un banco (make amc) hace varios sorteos para no perder mundos.

3.5.3. seed: reproducibilidad independiente del orden

Cuando varios problemas con setup aleatorio se generan en secuencia (en un bucle o un Makefile), los valores sorteados en cada problema dependerían del estado del generador en ese momento. El campo seed (entero) resuelve esto: antes de iterar las variantes, qbank siembra numpy.random y random con él. Así cada problema tiene su propia secuencia reproducible. También es la semilla base de por_partes(instances=N) cuando no se pasa base_seed.

3.5.4. setup como función (solo uso interactivo)

setup admite también una función sin argumentos que devuelve el diccionario de variables. Es cómodo en un cuaderno, pero un problema así no puede guardarse con save_problema (el código de una función no es recuperable); lo mismo ocurre con las lambdas escritas como funciones Python en semantica o precond. Escríbelos como cadenas si la pregunta va a vivir en un fichero.

4. El formato JSON

qbank convierte cualquier ProblemaTipo a JSON y lo reconstruye después. Es el formato en que se guardan las preguntas de un banco (lo que leen lint y los scripts de qbank-init).

4.1. Campos

{

  "tipo": "ProblemaTipo",
  "nombre": "L-01-Monotonia",
  "seed": 1,
  "setup": "import numpy as np\na = int(np.random.randint(1, 10))",
  "export": {"last_choice": true, "cols": 2, "instances": 6},

    ],

Clave Descripción
version "1".
tipo "ProblemaTipo" (o "ProblemaVF", ver el apéndice).
nombre Identificador; debe coincidir con el nombre del fichero sin .json y no contener : (rompe make).
seed Entero, null o ausente. Solo con setup aleatorio.
setup Código Python como cadena (saltos de línea como \n) o null.
export Opcional. last_choice (bool): opción por defecto. cols (int): columnas en AMC. instances (int): instancias con setup aleatorio.
componentes La lista plana: cadenas, objetos Supuesto y Cuestion y listas de ellos.

Cada Supuesto es un objeto con tipo, enunciado, semantica y precond; cada Cuestion añade exp. Las fórmulas y lambdas van como cadenas, exactamente como se escribirían en Python. Las barras de LaTeX se doblan (\\mathcal).

Puedes añadir claves propias de nivel superior, como "_nivel": "M" o "_tema": qbank las ignora al cargar y save_problema las conserva.

Regla para instances: con setup aleatorio, instances = max(1, ceil(60 / variantes por instancia)), para que la vista alumno tenga al menos 60 variantes; lint imprime el valor necesario.

5. Exportar a AMC (LaTeX)

Las funciones AMC generan el código LaTeX para Auto Multiple Choice: cada una devuelve una cadena con un bloque \element{...}, que el usuario escribe al fichero. El flujo completo (un .tex por pregunta, un documento que lo compila y los PDF de revisión) lo hacen los scripts de un proyecto qbank-init (make amc y make amc-student).

Las funciones no leen export del problema: pasa last_choice= y cols= en cada llamada (los scripts de un banco sí lo leen y se los pasan).

5.1. AMCblock

AMCblock(nombre, etiqueta, enunciado, cuestiones,
         last_choice=False, cols=1, profe=False, *,
         aux_latex="", last_choice_text="Ninguna de las anteriores")
Parámetro Descripción
nombre Nombre del grupo AMC (etiqueta LaTeX). Los : y _ se convierten en -.
etiqueta Identificador único de esta variante dentro del grupo.
enunciado Texto del enunciado ($$...$$ se convierte a \[...\], que automultiplechoice prefiere).
cuestiones Lista de tuplas (texto, correcto, activa[, exp]), la segunda componente de cada parte.
last_choice Si True, añade la opción por defecto con \lastchoices: correcta solo si las demás son falsas.
cols Columnas (>1 activa \begin{multicols}{N}\AMCBoxedAnswers).
profe Si True, vista profe: las cuestiones rechazadas por su precondición van en \explain{}.
aux_latex Instrucciones LaTeX extra dentro del bloque \element{}.
last_choice_text Texto de la opción por defecto.

etiqueta, partes = next(iter(p.por_partes()))
enunciado, cuestiones = partes[0]
print(AMCblock("MiCuestionario", etiqueta, enunciado, cuestiones, last_choice=True, cols=2))

 \begin{questionmult}{MiCuestionario-1}
  Considere $\mathcal{A}$ y que $\mathcal{A}\Rightarrow\mathcal{C}$. Entonces, con toda seguridad:
   \begin{multicols}{2}\AMCBoxedAnswers
      \begin{choices}

       \correctchoice{se da $\mathcal{A}$}

   \end{multicols}
 \end{questionmult} }

Para escribir todas las variantes de la vista alumno:

5.2. AMC_multipart — preguntas con varias partes

Un AMCblock por parte produciría dos preguntas con el mismo identificador y la segunda sin las hipótesis. AMC_multipart genera un único questionmult con un bloque de casillas por parte, cada uno con su propia opción por defecto si last_choice: 

AMC_multipart(nombre, etiqueta, enunciado, partes,
              last_choice=False, cols=1, profe=False, *,
              aux_latex="", last_choice_text="Ninguna de las anteriores")

partes es la lista de pares (enunciado, cuestiones) que devuelven por_partes() y por_partes_profe(); enunciado es un texto común previo, normalmente "" porque el de la primera parte ya contiene las hipótesis. Los demás parámetros son los de AMCblock. 

multi = load_problema("ejemplosManual/superheroes.json")      # tres partes
with open("preguntas_multi.tex", "w") as f:
    for etiqueta, partes in multi.por_partes():
        if len(partes) > 1:
            f.write(AMC_multipart("Superheroes", etiqueta, "", partes, last_choice=True))
        else:
            f.write(AMCblock("Superheroes", etiqueta, partes[0][0], partes[0][1], last_choice=True))

Recorre por_partes_profe() y escribe en directorio/nombre_profe.tex una pregunta AMC por mundo (con AMC_multipart si tiene varias partes), con todas las cuestiones de cada hueco marcadas y las rechazadas en \explain{}. problema puede ser un ProblemaTipo o un diccionario {nombre: ProblemaTipo}. directorio admite / final o no.

5.4. Integración en el documento AMC

Los ficheros generados se incluyen en el preámbulo del documento AMC con la orden \input{preguntas.tex}; dentro de \onecopy, \insertgroup[1]{MiCuestionario} inserta una variante por copia (sin el [1] se insertarían todas) y \shufflegroup las baraja. El README de la plantilla da el procedimiento completo; consulta la documentación de AMC para el formato del documento.

6. Exportar a Moodle (vía LaTeX)

Las funciones Quiz* escriben un fichero .tex autónomo que usa el paquete LaTeX moodle; al compilarlo se obtienen un PDF de revisión y el fichero nombre-moodle.xml importable en Moodle (Banco de preguntas → Importar → Formato Moodle XML). Como las de AMC, no leen export: pasa last_choice= e instances= (los scripts de un banco sí lo leen). 

Python (qbank)  →  nombre.tex  →  xelatex / pdflatex  →  nombre.pdf + nombre-moodle.xml  →  Moodle

El .tex compila con cualquier motor (su cabecera distingue pdflatex de xelatex o lualatex). Si lo compilas a mano, usa xelatex: el XML sale declarado en UTF-8. Con pdflatex el paquete moodle lo declara en iso-8859-1 aunque escribe en UTF-8 los caracteres que codchar no convierte (los signos ¿ y ¡, las mayúsculas acentuadas como Á o Ñ y la ü), y Moodle los mostraría mal (por ejemplo, Â¿ en lugar de ¿); los proyectos de qbank-init compilan con pdflatex y corrigen la declaración después (scripts/fix_moodle_xml.py, que make moodle ejecuta).

El paquete moodle se instala con tlmgr install moodle (TeX Live) o sudo apt install texlive-latex-extra (Debian/Ubuntu). Dos avisos: el paquete declara el XML en iso-8859-1 pero escribe algunos caracteres en UTF-8, y escapa mal el «<» dentro de los bloques cloze; los scripts de qbank-init corrigen ambas cosas (scripts/fix_moodle_xml.py). Si exportas a mano, revisa el XML.

7. Comprobación automática de preguntas (lint)

Antes de exportar conviene comprobar que la pregunta está bien construida. lint automatiza lo que de otro modo habría que mirar a ojo recorriendo todas las variantes. Acepta un ProblemaTipo, un dict o la ruta a un fichero, no modifica nada ni compila LaTeX, y devuelve una lista de Aviso(nivel, codigo, mensaje, donde) con nivel ERROR, AVISO o INFO, errores primero: 

for aviso in lint("ejemplosManual/ej_c_precond.json"):
    print(aviso)

INFO  [constante] falsa en los 2 mundos en que aparece (semantica literal)  @ comp 4[2]: $\det(A)$ puede ser cualquier número real
INFO  [constante] falsa en los 2 mundos en que aparece (semantica literal)  @ comp 5[3]: $A^{-1} = A^\top$ necesariamente
INFO  [constante] falsa en los 2 mundos en que aparece (semantica literal)  @ comp 6[2]: el sistema $Ax=b$ tiene siempre infinitas soluciones

Cada aviso lleva su nivel, su código entre corchetes, el mensaje y, tras @, dónde está: comp 4[2] es el componente 4 de la lista (contando desde 0), elemento 2. Aquí son tres INFO: tres distractores siempre falsos, puestos a propósito.

Un ERROR significa que la pregunta está rota; un AVISO hay que leerlo y decidir; un INFO es información. Las reglas, con el código de cada aviso:

mezcla (ERROR)
en alguna variante y parte todas las opciones son correctas o todas incorrectas, contando la opción por defecto si export.last_choice está activo (misma regla que los exportadores).
pocas-opciones (AVISO)
una parte muestra al alumno menos de tres opciones: el error típico de poner las opciones en una única lista de Cuestion (que sortea una). opciones (AVISO): una parte sin ninguna cuestión (típicamente, un texto suelto tras la última Cuestion; esa parte no da además mezcla), o con un número de opciones que varía entre variantes.
variantes
ERROR si la pregunta no genera ninguna variante válida. AVISO con menos de 16 variantes sin setup, o menos de 60 con setup (contando export.instances). INFO con más de 300: la vista alumno de AMC en un solo examcopy puede agotar la memoria de pdflatex.
ejecucion (ERROR)
el setup o el recorrido de las variantes lanzan una excepción.
constante (AVISO)
una Cuestion verdadera (o falsa) en todos los mundos en que puede aparecer, candidata a distractor memorizable. Es INFO si la semántica es el literal True o False (distractor deliberado) o una lambda con setup (la tabla de mundos usa un solo sorteo; compruébalo con la vista profe). solape (AVISO): dos Cuestion con el mismo texto en el mismo hueco pueden aparecer en un mismo mundo.
negacion
una semantica o precond usa -v('X') pero ningún Supuesto permite deducirlo (hace falta un unoDe que incluya v('X'), a cualquier profundidad, o un Supuesto que afirme o implique -v('X')). ERROR si v('X') es una alternativa de una lista; AVISO si niega un Supuesto suelto (siempre presente): nunca será cierta.
interp (ERROR)
queda algún @{var} sin sustituir en el texto renderizado (el escape @@{x}, que se imprime como «@{x}», no cuenta).
huerfana (AVISO)
una etiqueta v('X') usada en una Cuestion no aparece en ningún Supuesto (INFO si algún Supuesto es una lambda, porque entonces no se puede saber). sin-uso (INFO): una etiqueta declarada que ninguna Cuestion usa.
carga, tipo, nombre, estructura (ERROR)
el JSON no se puede leer o cargar (carga); no es un ProblemaTipo (tipo); el nombre no coincide con el fichero o lleva : o espacios, que los scripts del banco no admiten (nombre); alguna lista está vacía, mezcla tipos o va anidada, o export o seed están mal tipados (estructura; "seed": true tampoco vale). lista-1, seed, instances (AVISO): listas de un solo elemento, seed incoherente con el uso de aleatorios, instances > 1 sin setup.
texto
un % sin barra es ERROR (en LaTeX empieza un comentario y el PDF sale vacío o roto sin que pdflatex pare). Son AVISO: \% dentro de $…$ (Moodle lo pierde), °, «» y comillas rectas (no existen en la codificación del paquete moodle o salen como ”), \(…\) o \[…\] en vez de $…$ / $$…$$, citas a números de lección, @{ sin cerrar, dobles espacios fuera de las fórmulas, comillas simples, textos que parecen código lambda ns: (desde JSON no se evalúan). Las dos reglas del % se aplican también al texto interpolado con unos sorteos del setup (el mensaje lo indica con «en el texto interpolado»).
setup (INFO)
variantes por instancia e instances necesarias para llegar a 60.

tabla_mundos(problema) devuelve una tabla de texto con el valor de cada Cuestion (V, F, o - si la rechaza su precond) en cada combinación de Supuesto, para localizar distractores constantes y auditar la lógica. Con setup usa un solo sorteo (sembrado con seed), así que los mundos filtrados por precondiciones numéricas pueden no aparecer todos.

Desde la línea de órdenes (código de salida 1 si hay algún ERROR; --quiet omite los INFO y los ficheros sin avisos):

9. Preguntas frecuentes

9.1. ¿Por qué algunas variantes no se generan?

Si un Supuesto o una Cuestion tiene una precondición que no se satisface en una combinación determinada, esa variante completa se descarta. Es el comportamiento esperado: evita combinaciones de hipótesis incoherentes. En la vista profe, las cuestiones rechazadas se ven; un Supuesto rechazado hace desaparecer la variante también allí.

9.2. ¿Cómo incluyo texto LaTeX en los enunciados?

Los campos enunciado y exp son cadenas Python que se insertan tal cual en el .tex. Usa cadenas crudas (r"...") para no doblar las barras invertidas: 

Cuestion(r"$\mathbf{X}^\top\mathbf{X}$ es invertible", -v("Mcoli"))

En JSON cada barra se dobla: "$\\mathbf{X}^\\top\\mathbf{X}$".

9.3. ¿Puedo escribir un porcentaje, grados, comillas…?

El símbolo % es, en LaTeX, el inicio de un comentario: escribe siempre \% (y fuera de los dólares: al $5$\,\%). Nada de ° (usa ^\circ) ni de comillas angulares «» o rectas "…" (usa ``así''): el paquete moodle no las admite o las deforma. Acentos, ñ, ¿ y ¡ sí se pueden teclear. lint avisa de todo esto; la Guía lo explica.

9.4. ¿Cómo escribo display math?

Con $$...$$, nunca \[...\] ni \(...\) directamente: el paquete moodle necesita los dólares, y los exportadores AMC convierten $$...$$ a \[...\] automáticamente (automultiplechoice a veces produce errores «Missing $» con $$). Separa dos expresiones en línea contiguas con un espacio ($A$ $B$, no $A$$B$).

9.5. ¿Puedo incluir una figura en el enunciado?

Sí, con \includegraphics en el texto (el enunciado es LaTeX), pero cada destino la quiere de una forma. En AMC vale un PDF a tamaño natural; los documentos de la plantilla ya cargan graphicx: 

"Observe la figura. \\begin{center}\\includegraphics{fig.pdf}\\end{center} Entonces:"

El paquete moodle incrusta la imagen en el XML (en base64) y solo sabe de mapas de bits: hace falta un PNG del mismo nombre y compilar con pdflatex -shell-escape, porque llama a base64. Un patrón que funciona: generar fig.pdf y fig.png (p. ej. con pdftoppm -png -r 200), referenciar el PDF en el JSON y, en el script de Moodle, sustituir .pdf por .png en el .tex (con width igual a la anchura natural del PDF, para que Moodle no lo agrande); el banco de Probabilidad y Estadística del autor lo hace así en su scripts/gen_moodle.py. Si la ruta de la figura va en el setup como variable e interpolada con @{fig}, la misma pregunta sirve para los dos destinos. Ten en cuenta el tamaño: una figura en cada una de 150 variantes multiplica el XML.

9.6. ¿Para qué sirve codchar?

codchar(s) convierte las vocales acentuadas minúsculas y la ñ a secuencias LaTeX (á → \'{a}). Las funciones Moodle lo aplican automáticamente, porque el .tex que generan usa codificación OT1; no hace falta llamarlo a mano. Las mayúsculas acentuadas (como Á o Ñ), la ü y los signos ¿ y ¡ pasan tal cual: con xelatex salen bien; con pdflatex el XML queda mal declarado y lo corrige scripts/fix_moodle_xml.py de la plantilla (ver la sección 6). Para AMC no suele hacer falta si el documento principal usa inputenc con UTF-8.

9.7. ¿Cómo exporto varias preguntas a un mismo cuestionario Moodle?

Pasa un diccionario a QuizMoodle: todas van al cuestionario MiExamen, y cada clave da nombre a sus variantes (Seccion-A-1, Seccion-A-2, …): 

QuizMoodle("MiExamen", "salida/", {"Seccion-A": p_a, "Seccion-B": p_b}, last_choice=True)

Un banco de qbank-init guarda cada pregunta en su propio fichero, y el script scripts/merge_moodle_xml.py fusiona sus XML en _banco.xml.

10. Apéndice: API avanzada y compatibilidad

10.1. ProblemaVF — preguntas de verdadero/falso

ProblemaVF sirve para un formato distinto: un banco de afirmaciones del que se extrae aleatoriamente un subconjunto en cada variante. No usa cálculo proposicional; la corrección de cada ítem se indica con True o False. No lo revisa lint ni lo exportan los scripts de qbank-init: para un banco nuevo, una pregunta de tres huecos de ProblemaTipo cubre el mismo uso con todas las herramientas. 

ProblemaVF(enunciado, cuestiones, NumPreguntas)
Parámetro Descripción
enunciado Texto del enunciado común a todas las variantes.
cuestiones Lista de tuplas (texto, correcto).
NumPreguntas Cuántas afirmaciones se eligen aleatoriamente por variante. 
enunciado = "Indique qué afirmaciones son verdaderas:"
banco = [
    ("Todo alumno que va a clase aprueba",   False),
    ("Todo alumno que sabe aprueba",         True),
    ("Si suspenden todos es frustrante",     True),
    ("Si aprueban todos eres buen profesor", False),
]
import random
random.seed(42)
GenVar = iter(ProblemaVF(enunciado, banco, 3))  # 3 ítems por variante

for _ in range(2):
    etiqueta, enunc, cuestiones = next(GenVar)
    print(f"Variante {etiqueta}: {enunc}")
    for texto, correcto in cuestiones:
        print(f"  {'✓' if correcto else '✗'} {texto}")

Variante 1: Indique qué afirmaciones son verdaderas:
  ✗ Todo alumno que va a clase aprueba
  ✗ Si aprueban todos eres buen profesor
  ✓ Todo alumno que sabe aprueba
Variante 2: Indique qué afirmaciones son verdaderas:
  ✓ Todo alumno que sabe aprueba
  ✗ Todo alumno que va a clase aprueba
  ✓ Si suspenden todos es frustrante

Se exporta con AMC_VF(nombre, etiqueta, enunciado, cuestiones) (un bloque por variante) y QuizVFMoodle(nombre, directorio, GenVar, num) (num variantes). Se guarda y carga en JSON sin restricciones.

10.3. Editor visual en Jupyter (ProblemaTipoEditor)

ProblemaTipoEditor es un formulario interactivo para diseñar un ProblemaTipo desde un cuaderno de Jupyter, sin escribir la lista de listas a mano. Requiere ipywidgets: 

pip install "calcprop-qbank[jupyter]"

(la orden con git+https://… de la instalación rápida ya incluye el extra [jupyter]).

En JupyterLab ≥ 4 es necesario que la extensión @jupyter-widgets/jupyterlab-manager esté habilitada: compruébalo con jupyter labextension list. Si el widget se muestra como texto (VBox(children=...), ejecuta una sola vez desde el terminal: 

mkdir -p ~/.local/share/jupyter/labextensions/@jupyter-widgets
ln -sfn $(python -c "import jupyterlab_widgets, os; \
  print(os.path.dirname(jupyterlab_widgets.__file__))")/labextension \
  ~/.local/share/jupyter/labextensions/@jupyter-widgets/jupyterlab-manager

y reinicia JupyterLab (en Jupyter Notebook clásico no hace falta). 

from qbank import ProblemaTipoEditor
editor = ProblemaTipoEditor()                   # editor vacío
editor = ProblemaTipoEditor('mi_problema.json') # cargar desde fichero
p = editor.to_problema()                        # ProblemaTipo listo para iterar
d = editor.to_dict()                            # dict JSON equivalente
save_problema(editor.to_problema(), "mi_problema.json")   # o el botón 💾 Guardar

El editor no tiene un método save: para guardar, usa el botón 💾 Guardar o pasa editor.to_problema() a save_problema, como en la última línea del bloque.

El formulario tiene una cabecera (Nombre:, Setup: con el campo semilla:, y Export: con la casilla last_choice y el campo cols:), la lista de huecos y una barra de botones. Cada hueco (Hueco 1, Hueco 2, etc.) tiene un tipo, texto, supuestos o cuestiones, y sus alternativas (+ alt): filas con enunciado, semántica, precondición y, en las cuestiones, explicación. Los botones de cada hueco lo suben o bajan (▲ / ▼), insertan otro hueco debajo (＋) o lo borran (✕); el botón + hueco añade uno al final. La barra inferior tiene ▶ Preview (genera hasta N variantes, con la casilla vista profe), { } JSON y </> .py (muestran el JSON o el guion Python), 💾 Guardar y 📂 Cargar (en el fichero indicado) y ⬇ .json / ⬇ .py (descargas al navegador). Al guardar conserva las claves de export que el formulario no edita (como instances) y las claves propias del JSON. ejemplosManual/Demo.ipynb (sección 8) lo muestra en uso.
